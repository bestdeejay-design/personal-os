## 1. Видение продукта

**Personal OS** — личный операционный центр для тех, кто хочет держать всё
под контролем: заметки, задачи, проекты, календарь, файлы — в одном месте,
с полным контролем над данными, без облаков и подписок.

### Проблема

Существующие инструменты разрозненны:
- Заметки в Obsidian/Notion, задачи в Todoist/TickTick, календарь в Google/Apple
- Нет связей между сущностями
- Нет единого поиска
- Нет агента, который держит в тонусе
- Данные в облаках — нет приватности

### Решение

Personal OS объединяет всё в одном месте с общей системой связей (профили,
теги, проекты), единым семантическим поиском и агентом, который не спамит,
но вовремя напоминает и предлагает действия.

### Целевая аудитория

Разработчики, продакт-менеджеры, фрилансеры — технически подкованные
пользователи, ценящие контроль над данными и эффективность.

## 2. Что уже есть и куда идём

### Текущее состояние

| Раздел | Что работает | Чего не хватает |
|--------|-------------|-----------------|
| Заметки | Markdown, теги, профили, проекты, ручная сортировка, поиск | Шаблонов, авто-классификации |
| Канбан | Колонки, drag-n-drop, приоритеты, фильтры, ранжирование | Тегов, повторяющихся задач |
| Календарь | Внешние календари (Google/Yandex), RRULE, экспорт ICS | Создания своих событий, drag-n-drop |
| Файлы | Загрузка, скачивание, метаданные, поиск | Превью, файлового инбокса |
| Проекты | CRUD, панель элементов, связи | Наложения на календарь |
| Поиск | Семантический + ILIKE | Умных фильтров, автокомплита |
| Агент | 4 триггера, DND, Inbox, дайджесты | Голоса, контекста, классификации, чата |
| Timeline | Единая лента | Возможности создавать из ленты |
| Аналитика | Метрики, графики, per-profile | — |

### Куда идём

Personal OS должен стать продуктом, который:
1. **Не требует усилий на ввод данных** — шаблоны, голосовой ввод, авто-классификация
2. **Даёт полный контроль над временем** — календарь как инструмент планирования
3. **Помогает не забывать** — агент с контекстными подсказками
4. **Адаптируется под пользователя** — кастомизация, темы, профили
5. **Работает везде** — десктоп, адаптив под планшет

## 3. Фаза A — Календарь становится инструментом

**Цель:** Превратить календарь из пассивного просмотрщика в активный
инструмент планирования. Довести канбан до уровня заметок по функциональности.

---

### A1. Создание и редактирование своих событий

**Что делаем:**
- Кнопка «+ Событие» в календаре (рядом с заголовком)
- Модальное окно с полями: название, дата/время, весь день, профили,
  локация, проект, повторение (ежедневно/еженедельно/ежемесячно),
  описание в Markdown
- Редактирование существующих событий по клику
- Удаление событий

**Как улучшает продукт:**
- Перестаём быть заложниками внешних календарей — можно создать встречу
  напрямую в Personal OS
- Полноценная замена Google Calendar для базовых сценариев
- Единая точка ввода всех временных событий

**Технически:**
- Переиспользовать существующий `POST /api/calendar` и `PATCH /api/calendar/:id`
- Фронт: модалка с формой, повторно используемая для create/edit

---

### A2. Drag-n-drop в недельной сетке

**Что делаем:**
- Перетаскивание событий в WeekView вертикально (изменение времени)
- Перетаскивание событий между днями (изменение даты)
- Изменение длительности резистом (нижняя граница события)
- Анимация иsnap-сетка (интервал 30 минут)

**Как улучшает продукт:**
- Критически для планирования дня — переставить встречу в 2 клика мышкой
- Убирает главный friction календаря: «открыть событие → изменить поле → сохранить»
- Приближает к поведению Google Calendar / Fantastical

**Технически:**
- `pointer-events` / `mousedown` + `mousemove` на `EventBlock` компонентах
- При отпускании → `PATCH /api/calendar/:id` с новыми start/end
- Ресайз — отдельный хендлер на нижней границе

---

### A3. Recurring-задачи в канбане

**Что делаем:**
- Поле `recurrence jsonb` у tasks (уже есть у meetings — переиспользуем)
- UI: при создании/редактировании задачи выбор повтора
- При завершении задачи с recurrence → автоматическое создание новой
  задачи с теми же полями, сдвинутой датой
- Поддержка: ежедневно, еженедельно (с выбором дней), ежемесячно

**Как улучшает продукт:**
- Закрывает сценарий «Каждую неделю проверять почту», «Ежедневный лог»
- Без этого канбан не подходит для регулярных действий
- Единая система рекуррентности с календарём

**Технически:**
- `tasks.recurrence jsonb`: `{ "freq": "weekly", "interval": 1, "byDay": ["MO","FR"] }`
- При `PATCH /api/tasks/:id` с `status: "done"` — проверка `recurrence`
- Если есть → `INSERT INTO tasks` с новыми полями + `due_date + interval`
- Фронт: select «Не повторять / Каждый день / Каждую неделю / Каждый месяц»

---

### A4. Теги в канбане

**Что делаем:**
- Колонка `tags jsonb` в таблице `tasks` (как у `notes`)
- UI: поле ввода тегов при создании/редактировании задачи
- Отображение тегов в карточке задачи
- Фильтрация по тегам (сверху канбана — chips как у профилей)
- Поиск по тегам через глобальный поиск

**Как улучшает продукт:**
- Заметки с тегами — задачи без тегов → разрыв экосистемы
- Группировка задач по темам: `баги`, `дизайн`, `встречи`
- Быстрая фильтрация без переключения проектов
- Единая система тегов для всех сущностей

**Технически:**
- `ALTER TABLE tasks ADD COLUMN IF NOT EXISTS tags jsonb DEFAULT '[]'`
- Переиспользовать `NoteTagInput` (или аналог) для задач
- Search уже умеет искать по `tags` в заметках → расширить на tasks

---

### Итог Фазы A

После этой фазы:
- Календарь становится полноценным инструментом планирования
- Канбан догоняет заметки по функциональности
- Закрыты 3 из 5 P0-блокеров пользователя

## 4. Фаза B — Шаблоны и умный поиск

**Цель:** Ускорить ввод данных в 2-3 раза и сделать поиск реально полезным.

---

### B1. Шаблоны заметок

**Что делаем:**
- Новая entity `templates` в БД:
  `id, name, type (note/task), body, default_tags, default_profile_ids, created_at`
- 4 встроенных шаблона:
  - **Встреча:** `title: "Встреча: {date}"`, body с секциями «Участники», «Обсудили», «Решили»
  - **Задача:** `title: ""`, body с чек-листом
  - **Идея:** `title: ""`, body со свободным полем
  - **Дневник:** `title: "Дневник: {date}"`, body с секциями «Что сделано», «Мысли», «Планы»
- UI: кнопка «Из шаблона» при создании заметки → выбор шаблона → предзаполненная форма
- Возможность создавать свои шаблоны на основе существующих заметок
- API: `GET /api/templates`, `POST /api/templates`, `DELETE /api/templates`

**Как улучшает продукт:**
- Создание заметки по шаблону — 2 клика вместо 5
- Структурированные заметки вместо пустого листа
- Дисциплина ведения записей

---

### B2. Шаблоны задач

**Что делаем:**
- То же самое для задач: шаблоны с предзаполненными полями
- Встроенные: «Баг» (приоритет High), «Задача на неделю», «Ревью кода»
- Применение при создании задачи из канбана

---

### B3. Умный поиск

**Что делаем:**
- Поле поиска с автокомплитом (dropdown подсказок при вводе)
- Фильтры через синтаксис: `type:note`, `tag:встреча`, `project:название`, `profile:work`
- Фильтры через чипы (как профили): тип, тег, проект
- Сохранение последних 5 запросов
- Подсветка совпадений в результатах

**Как улучшает продукт:**
- Поиск становится быстрым и точным
- Фильтр по типу: «покажи только задачи» — без лишнего шума
- Автокомплит экономит время

---

### B4. Экспорт всего

**Что делаем:**
- Кнопка «Экспорт» в настройках
- Сервер собирает все данные в ZIP:
  - Заметки → `.md` файлы (каждый отдельно)
  - Задачи → `tasks.json`
  - Проекты → `projects.json`
  - Календарь → `calendar.ics`
  - Файлы → копируются в архив
- Прогресс-бар при генерации

**Как улучшает продукт:**
- Бэкап всех данных одной кнопкой
- Возможность переноса на другую машину
- Совместимость: md-файлы открываются любым редактором

---

### Итог Фазы B

После этой фазы:
- Ввод данных ускоряется в 2-3 раза
- Поиск становится точным и быстрым
- Пользователь всегда может сделать полный бэкап

## 5. Фаза C — Новые разделы: привычки и контакты

**Цель:** Расширить покрытие жизненных сценариев — учёт привычек
и минимальная адресная книга.

---

### C1. Timeline — действия из ленты

**Что делаем:**
- Сейчас Timeline read-only: показывает встречи + задачи + заметки в единой ленте
- Добавляем: кнопку «Создать заметку» / «Создать задачу» / «Создать встречу»
  из определённого момента на таймлайне
- При создании дата/время предзаполняются из позиции на таймлайне

**Как улучшает продукт:**
- Таймлайн из пассивного просмотра становится точкой входа для планирования
- Сценарий: «Вижу, что в 14:00 пусто → создаю встречу в один клик»

---

### C2. Habit Tracker

**Что делаем:**
- Новая entity `habits`:
  ```sql
  CREATE TABLE habits (
    id uuid PK,
    name text NOT NULL,
    description text,
    frequency text NOT NULL,  -- daily / weekly / custom
    custom_cron text,         -- для кастомных расписаний
    profile_ids jsonb,
    project_id uuid FK,
    tags jsonb,
    color text,
    created_at timestamptz,
    archived boolean
  );
  ```
- Таблица `habit_logs`:
  ```sql
  CREATE TABLE habit_logs (
    id uuid PK,
    habit_id uuid FK ON DELETE CASCADE,
    date date NOT NULL,
    done boolean NOT NULL DEFAULT true,
    note text,
    UNIQUE (habit_id, date)
  );
  ```
- View «Привычки»: список привычек с календарём чек-инов
- Streak-счётчик (текущая серия выполнения)
- Виджет на дашборде (Фаза E)
- Фильтрация по профилям

**Как улучшает продукт:**
- Закрывает сценарий «читаю книгу каждый день», «тренировка по утрам»
- Streak мотивирует не пропускать
- Привязка к профилям: Work привычки vs Home привычки

---

### C3. Контакты

**Что делаем:**
- Новая entity `contacts`:
  ```sql
  CREATE TABLE contacts (
    id uuid PK,
    name text NOT NULL,
    email text,
    phone text,
    notes text,
    profile_ids jsonb,
    tags jsonb,
    linked_project_id uuid FK,
    linked_meeting_id uuid FK,
    created_at timestamptz
  );
  ```
- View «Контакты»: список, поиск, фильтр по профилям
- Быстрое создание заметки/задачи с привязкой к контакту
- Иконки для email/phone (кликабельные `mailto:` / `tel:`)

**Как улучшает продукт:**
- Минимальная адресная книга без ухода в другое приложение
- Связь контактов с проектами и встречами
- Поиск по контактам через глобальный поиск

---

### Итог Фазы C

- Personal OS покрывает новые жизненные сценарии
- habits + contacts = P2-фичи, которых ждут пользователи
- Каждый новый раздел — повод вернуться в продукт

## 6. Фаза D — Полноценный AI-агент

**Цель:** Превратить агента из «напоминалки» в ассистента, который понимает
контекст, действует проактивно и отвечает на вопросы.

---

### D1. Голосовые задачи

**Что делаем:**
- Кнопка микрофона в шапке приложения (всегда видна)
- Распознавание речи → парсинг намерения через LLM
- Интенты:
  - `"Напомни завтра в 15:00 позвонить в банк"` → задача с дедлайном + напоминание
  - `"Создай заметку идея для дизайна"` → заметка с тегом `идея`
  - `"Запиши что Петя сказал прислать макет"` → заметка с телом текста
- После распознавания — модалка подтверждения (не выполнять слепо)
- fallback: если LLM не смог распарсить — просто создать заметку с текстом

**Как улучшает продукт:**
- Главный сценарий S1 из SPEC: запись идей без клавиатуры
- Скорость ввода: голосом в 3-4 раза быстрее текста
- Создание задач не отвлекаясь от текущего дела

---

### D2. Контекстные предложения агента

**Что делаем:**
- Агент анализирует контекст при тике:
  - Какой профиль активен
  - Какое время суток
  - Что происходило за последний час (завершённые встречи, созданные заметки)
  - Какие задачи с ближайшим дедлайном
- Генерирует 1-2 предложения (не спамить!):
  - «У тебя через 30 минут встреча с командой. Подготовить повестку?»
  - «Ты давно не смотрел проект "Дизайн" — там 3 задачи без статуса»
  - «Вечер, может, записать что сделал за день?»
- Предложения показываются в Agent Inbox с кнопками быстрого действия

**Как улучшает продукт:**
- Агент чувствует контекст — не бесит, а помогает
- Пользователь чувствует, что система «помнит» о нём
- Повышается вовлечённость и полнота данных

---

### D3. Авто-классификация заметок

**Что делаем:**
- При создании заметки — асинхронный вызов LLM:
  - Предложить теги (анализ текста)
  - Предложить профиль (если не указан)
  - Предложить связанный проект (похожие заметки/задачи)
- Результат — не автоматическое применение, а уведомление в Agent Inbox:
  «Я бы отнёс эту заметку к профилю Work и проекту "Сайт". Согласен?»
- Со временем: если пользователь всегда соглашается — применять авто

**Как улучшает продукт:**
- Пользователь не думает о классификации — агент делает это за него
- Данные становятся более структурированными без лишних действий
- Поиск работает лучше, когда всё размечено

---

### D4. Чат с данными

**Что делаем:**
- Новый чат-интерфейс (вкладка в Agent Inbox или отдельный view)
- Пользователь пишет вопрос: «Что у меня по проекту X?», «Какие задачи с дедлайном на этой неделе?»
- Агент:
  1. Переводит вопрос в SQL или search query
  2. Ищет по данным (RAG + поиск)
  3. Генерирует ответ с ссылками на сущности
- Примеры ответов:
  - «По проекту "Сайт": 3 задачи в работе, дедлайн ближайший — пятница. Вот список: ...»
  - «На этой неделе у тебя 5 встреч, 2 дедлайна. Самая загруженная — среда.»
- Сохранение истории диалогов (сессия)

**Как улучшает продукт:**
- Natural language interface к личным данным
- Не нужно помнить, где что лежит — просто спросить
- Киллер-фича для технических пользователей

---

### Итог Фазы D

- Агент из «напоминалки» превращается в ассистента
- Голосовой ввод + авто-классификация + чат = SPEC P2/P3 в полном объёме
- Киллер-фича, которая отличает Personal OS от всех других инструментов

## 7. Фаза E — Полировка и доведение до ума

**Цель:** Сделать продукт визуально приятным, адаптивным и готовым
к показу другим.

---

### E1. Адаптивная вёрстка

**Что делаем:**
- Сайдбар → hamburger-меню на узких экранах (< 900px)
- Календарь: недельная сетка не ломается на 800px (сейчас только 1 @media)
- Все view: минимальная ширина контента, горизонтальный скролл вместо поломки
- Touch-мишени: кнопки не меньше 44×44px
- Тестирование на 1024px (iPad), 768px (iPad mini), 375px (iPhone)

**Как улучшает продукт:**
- Возможность работать с iPad/ноутбука в поездке
- Пользователь не теряет функциональность при маленьком окне браузера
- Без этого нельзя показывать продукт «не разработчикам»

---

### E2. Кастомизация дашборда

**Что делаем:**
- Новая страница «Дашборд» (стартовая по умолчанию)
- Виджеты (перетаскиваемые, настраиваемые):
  - **Часы / приветствие**
  - **Задачи на сегодня** (с дедлайном)
  - **Ближайшие встречи** (из календаря)
  - **Последние заметки**
  - **Прогресс привычек** (streak)
  - **Погода** (опционально, через open API)
- Кнопка «Настроить» → показать/скрыть виджеты, изменить порядок
- Сохранение в localStorage / настройках

**Как улучшает продукт:**
- При входе — сразу видно главное (не надо переключаться между разделами)
- Каждый пользователь настраивает под себя
- Виджет привычек мотивирует

---

### E3. Контрастность тёмной темы

**Что делаем:**
- Аудит всех экранов в тёмной теме
- Проверка контрастности текста (WCAG AA — минимум 4.5:1)
- Фикс: текст на цветных фонах, placeholder-ы, muted-текст
- Проблемные места сейчас: сайдбар, тёмные кнопки, выделенный текст

**Как улучшает продукт:**
- Тёмная тема перестаёт «резать глаза»
- Продукт выглядит профессионально
- Доступность для людей с нарушениями зрения

---

### E4. Превью файлов

**Что делаем:**
- Изображения (jpg, png, gif, svg, webp) — превью в галерее
- PDF — встроенный просмотрщик (PDF.js)
- Текстовые файлы — подсветка синтаксиса
- Видео/аудио — встроенный плеер
- По клику на превью — полноэкранный режим

**Как улучшает продукт:**
- Файлы перестают быть «чёрным ящиком»
- Можно просматривать изображения и PDF без скачивания
- Единый медиа-центр
